# ADR-2026-009: OneRoster As The Shared Academy LMS Exchange Standard

**Date:** 2026-09-12
**Status:** ACCEPTED
**Deciders:** Architecture Council
**Tags:** oneroster, academy, lms, interoperability, sis

## Context

ChurchCore Academy is the SIS and system of record. ChurchCore LMS is the learning runtime. The products need one professional, auditable standard for roster, enrollment, class, course, academic-session, and gradebook exchange.

The LMS repository already contains a OneRoster CSV validation, staging, preview, apply, provenance, omission-reconciliation, and identity-linking implementation. Academy is adding the matching OneRoster export contract so the two systems can align through the same standard rather than custom Moodle/Canvas-shaped payloads.

## Decision

ChurchCore LMS will treat OneRoster as the shared exchange standard for Academy alignment.

The LMS will:

1. Import Academy-produced OneRoster 1.2 CSV packages.
2. Preserve standalone mode when no Academy or OneRoster source is configured.
3. Keep validation-before-redaction, service-only apply, tenant-scoped RLS, source locks, idempotency, provenance links, and managed-field guards.
4. Require explicit identity linking or approved provisioning before roster users become LMS accounts.
5. Return grades and progress through reviewed OneRoster Gradebook Service style payloads before Academy posts official records.

## Consequences

- LMS import work is no longer a one-off admin upload feature; it is the receiving side of the Academy/LMS contract.
- OneRoster-owned records must remain visibly managed and protected from native edits that would break source alignment.
- Privileged LMS roles cannot be created or escalated by roster source data.
- Academy export, scheduled exchange, REST rostering, guardians, and result return remain phased work until verified.
