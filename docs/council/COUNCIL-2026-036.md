# COUNCIL-2026-036: Teacher ↔ Guardian Direct Messaging

**Status:** RATIFIED — Implemented & Verified

**Tags:** messaging, guardians, teachers, privacy, audit, rls

## Context

ChurchCore LMS provides a Guardian Portal (`/guardian`) where parents and guardians monitor academic progress, attendance, and certificates for their linked students. While teachers can send general announcements, there is currently no direct, secure two-way communication channel between teachers and guardians regarding specific student enrollments.

Council Review 3 and ministry pilot feedback identified Teacher ↔ Guardian messaging as a top priority for K-12 Christian academies and youth ministry discipleship.

---

## Council Positions & Architectural Guardrails

- **The Security Lead:** Guardians must **only** be able to initiate direct threads with teachers who are actively assigned to a course or section in which their verified ward is currently enrolled. Cross-tenant and unverified student queries must be strictly rejected at the database RLS layer.
- **The Data Engineer:** Introduce thread categorization (`thread_type: 'direct'`) linking the message thread directly to the student enrollment context.
- **The Architect:** Seamlessly integrate with the existing `useMessages` hook, realtime subscriptions, and the `send-guardian-notifications` Edge Function / Resend email bridge so offline teachers or guardians receive instant email alerts with unread message digests.
- **The Product Owner:** Provide dedicated "Message Instructor" buttons within the Guardian Portal student view and a "Guardian Conversations" filter within the Teacher Inbox.

---

## Technical Specifications & Schema Plan

### 1. Server Action & Boundaries
- Server action `sendGuardianTeacherMessage({ studentUid, courseId, message })` in `src/app/actions/messages.ts`.
- Validates active guardian link via `guardian_links`.
- Validates student enrollment in course via `enrollments`.
- Resolves instructor from `courses.owner_id`.
- Auto-formats contextual thread headers (`[Guardian Inquiry regarding Student in Course]`).

### 2. UI Surfaces
- Component `ContactTeacherModal.tsx` in `src/components/guardian/`.
- Integrated directly into `src/app/guardian/[studentId]/page.tsx` on every enrolled course card.

# COUNCIL-2026-036: Rubric Grading

**Status:** DRAFT — pending council vote and owner approval
**Date:** 2026-09-26
**Council:** Architecture Council, ChurchCore LMS (vote pending)
**Related:** COUNCIL-2026-030 (gradebook grid), `gradeSubmission()` / `setGradeCell()`, `block_submissions`
**Tags:** assessment, grading, teachers, schools

## Context

Teachers grade assignments and discussions with a single score and free-text feedback. Schools, Bible institutes and seminaries expect rubrics: named criteria with performance levels, shared with students before they submit and applied consistently. Every general LMS has them, and they are a checkbox in school evaluations.

## Decision

1. **Rubric model:**
   - A rubric is a reusable, org-owned set of criteria. Each criterion has a title, description and ordered levels (label, points, description).
   - Rubrics are created at `/admin/rubrics` (admins and managers) or inline from the assignment builder (teachers, scoped to their courses).
2. **Attach** a rubric to assignment and discussion blocks. Students see it on the block before submitting.
3. **Grade with the rubric** in submission review and in a side panel of the gradebook grid. The teacher picks a level per criterion, the score is computed (sum, optionally scaled to the block's max points), and comments are per criterion. A manual override of the total is allowed but recorded.
4. **Students see their rubric result**, including the level chosen and comments, on their submission and in the student report.
5. **Reporting:** a per-criterion average across a course in the instructor report, showing where the class struggles.

## Amendments Adopted

Proposed; binding once voted.

1. **Snapshots.** A rubric attached to a block is snapshotted when the first submission is graded. Editing the rubric afterwards doesn't change existing grades; a new version applies to later grading only.
2. Grading through a rubric uses the same authorization as `gradeSubmission()`, including the course-ownership check for teachers (COUNCIL-2026-030). No separate permission path.
3. Rubric scores flow into the existing grade fields, so guardian views, reports, certificates and the gradebook need no parallel logic.

## Test Surfaces

- `page:/admin/rubrics`: route table row (admin, manager); `flows/authoring.spec.ts` (create rubric, attach to assignment).
- New actions `rubrics.upsertRubric`, `rubrics.attachRubric`, `rubrics.gradeWithRubric`: `flows/rubrics.spec.ts` (grade → student sees levels → report shows the criterion average) plus unit tests for scoring and scaling.
- pgTAP: rubric RLS (org isolation, a teacher limited to their own courses), snapshot immutability.
