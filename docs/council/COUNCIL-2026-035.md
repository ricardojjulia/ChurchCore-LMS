# COUNCIL-2026-035: Self-Serve Tenant Signup & Automated Trial Provisioning

**Status:** RATIFIED - Implemented & Verified
**Date:** 2026-09-29
**Council:** Architecture Council, ChurchCore LMS (6/6 unanimous)
**Related:** COUNCIL-2026-026, COUNCIL-2026-027, COUNCIL-2026-031, ADR-2026-003
**Tags:** signup, onboarding, multi-tenant, billing, trial, security

---

## Context

ChurchCore LMS is transitioning from a managed pilot deployment into a self-service SaaS product for churches, ministries, Christian schools, and seminaries. Previously, tenant organizations could only be created by platform administrators via `/platform/actions.ts`.

To enable friction-free adoption while preserving multi-tenant isolation, anti-abuse defenses, and database integrity, ChurchCore LMS requires a public self-service signup flow that provisions an isolated organization, an administrative account, default academic terms, welcome starter content, and an automated 14-day trial without requiring upfront credit card entry.

---

## Council Positions

- **The Architect:** Organization signup must atomically create the tenant row, assign the administrative role in `app_metadata`, seed default academic structure, and initialize onboarding state. Slugs must be strictly validated, lowercase alphanumeric, and protected against collisions and system route shadowing.
- **The Security Lead:** Protect the public signup endpoint with Cloudflare Turnstile anti-bot verification and password complexity checks. Prevent privilege escalation by ensuring `app_metadata` is exclusively written server-side by the service client.
- **The Product Owner:** Deliver a delightful 2-minute onboarding experience. New organizations receive a 14-day free trial with full feature access (AI tutor, guardian portal, leaderboard, gradebook) and pre-seeded starter course templates.
- **The QA Lead:** Require 100% test surface coverage (`covers('page:/signup')` and `covers('action:tenant-signup.signupTenant')`). Validate slug sanitization, reserved word rejection, duplicate handling, and transactional seeding.
- **The Data Engineer:** Ensure all seed entities (terms, courses, blocks, announcements) correctly reference the newly created `org_id` and the administrator's profile `uid`.
- **The Engineer:** Implement a standalone server action `signupTenant` and a modern, responsive `SignupForm` component adhering to ChurchCore design system standards.

---

## Decisions

1. **D1:** Introduce public route `/signup` with a multi-tenant self-service registration form.
2. **D2:** New self-serve organizations start on plan `free`, status `trial`, with `trial_ends_at` set to 14 days from registration.
3. **D3:** Validate organization slugs against a strict regex (`^[a-z0-9]+(?:-[a-z0-9]+)*$`) and reserve system paths (`admin`, `platform`, `api`, `auth`, `join`, `signup`, `login`, `billing`, `dashboard`, `settings`, `demo`, `system`, `app`, `help`).
4. **D4:** Atomically seed default onboarding entities upon creation:
   - Initial academic term (`Academic Year 2026–2027`)
   - "Welcome to Your Academy" starter course with page, video, and quiz blocks
   - Welcome community announcement
5. **D5:** Integrate Cloudflare Turnstile validation with safe test-environment bypass.
