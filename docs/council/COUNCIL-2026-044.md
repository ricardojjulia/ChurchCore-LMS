# COUNCIL-2026-044: Backlog Close-Out (Block Types, Cohort Editing, Housekeeping)

**Status:** RATIFIED — in implementation (Sprint 5)
**Date:** 2026-09-26
**Council:** Architecture Council, ChurchCore LMS (6/6 approve, 2026-09-26; owner approved the Q4 plan the same day)
**Related:** `tests/surface/exemptions.json` (`action:cohorts.updateCohort`, expires 2026-11-20), the `block_types` table, `src/components/builder/NodeForm.tsx`, `docs/factory-status.md`
**Tags:** tech-debt, builder, cohorts, cleanup

## Context

Several small open items are known:

1. **Placeholder block types.** `block_types` defines `survey`, `flashcard_set`, `checklist`, `section` and `certificate`, which have no builder form and no player. `scorm` is handled by COUNCIL-2026-042. Authors never see them, but they are dead schema.
2. **`updateCohort` has no UI caller.** The cohort detail page has no edit form. Its test-surface exemption expires on **2026-11-20**, after which the release gate fails.
3. **`docs/factory-status.md` is stale.** It still describes v0.26.6 and was superseded by the 2026-09-26 status report.

## Decision

1. **Build three block types that have real teaching value:**
   - **Survey:** ungraded questions (scale, choice, text). Results are aggregated for the teacher and anonymous per org setting. Useful for class feedback and spiritual-gifts inventories.
   - **Flashcard set:** front/back cards, flip-through study, and optional self-rated recall. Completion when every card has been viewed.
   - **Checklist:** a learner ticks off items ("Read Romans 1–3", "Meet with a mentor"). Completion when every required item is ticked. It maps naturally to ChurchCore "next steps".
2. **Remove `section` and `certificate`** from `block_types`, after a data check that no rows use them. Sections are covered by `module_header`; certificates are issued at course level.
3. **Add a cohort edit form** on `/admin/cohorts/[id]` wired to `updateCohort` (name, description, program track, status — `global_cohorts` has no date or capacity columns; add them to the form if a later migration introduces them), with a flow test. Remove the exemption.
4. **Housekeeping:** rewrite `docs/factory-status.md` as a pointer to the current status report and implementation plan (done in the roadmap PR), and keep `tests/surface/exemptions.json` empty.

**6/6 approve.** The Security Lead's and QA Lead's conditions are binding.

## Amendments Adopted


1. Every new block type ships a builder form, a player, completion semantics in `sync_my_course_progress`, and a `BlockPlayer` case in the same PR. No partial block types.
2. Survey responses marked anonymous are stored without the respondent's uid, not merely hidden. The choice can't be changed once responses exist.
3. Removing block types is a migration that fails loudly if any `course_blocks` row still references them.
