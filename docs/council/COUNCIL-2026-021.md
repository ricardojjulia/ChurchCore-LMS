# COUNCIL-2026-021: Preserve Platform Group Reads During Tenant Repair

**Status:** RATIFIED — Pending implementation

**Tags:** security, groups, platform-admin, regression

## Context and deliberation

PR #5 adds restrictive active-tenant policies to four group tables. Existing
permissive SELECT policies explicitly permit platform administrators, whose
identity is held in `platform_admins` and need not have a tenant profile. The
restrictive predicates inadvertently deny their established read access.

- **The Architect:** Preserve the separate platform identity plane and existing
  policy composition. Vote: Yes.
- **The Engineer:** Add a forward migration; leave the reviewed historical
  migration intact. Bind member removal to its supplied section. Vote: Yes.
- **The Security Lead:** Restore only the existing `is_platform_admin()` exception
  in the restrictive boundary; retain all permissive operation checks. A
  platform identity with no tenant role must still have no group write grant.
  Ordinary staff remain constrained to their active tenant. Vote: Yes.
- **The Product Owner:** Restore operator visibility while preserving learner
  privacy; give the thread-title input an accessible name. Vote: Yes.
- **The QA Lead:** Reproduce denied platform reads first; verify four table reads,
  denied writes, ordinary cross-tenant/suspended/anonymous denial, and invalid
  section/member removal with real SQL and action tests. Vote: Yes.
- **The Data Engineer:** No table, identity or enrollment model changes, no data
  deletion, and no cloud migration. Test on disposable local data. Vote: Yes.

## Decision and amendments

1. Amendment 3 of COUNCIL-2026-020 retains the existing platform-admin SELECT
   exception alongside the active-tenant boundary for ordinary tenant actors.
2. Add `is_platform_admin() OR (current_user_tenant_active() AND
   org_id = current_user_org_id())` to both clauses of the four restrictive
   group policies. Existing permissive policies still decide allowed operations.
3. Do not broaden group RPCs to cross-tenant reads or grant platform write access.
4. Preserve main's controlled Vercel release and all architect/production gates.
   Academy and later OneRoster milestones remain outside this repair.
