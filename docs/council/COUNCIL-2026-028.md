## Context

Course completion certificates were already fully shipped prior to this session — `course_certificates` table, `issue_certificate` RPC, `/api/certificates/[id]/pdf` (via `@react-pdf/renderer`), the `/certificates` learner page, and Resend email notification. The genuine gap: no way for a third party (an employer, a pastor, a congregation) to verify a certificate's authenticity without an account. Every consumer credentialing flow this project competes with treats a public, shareable verification link as table stakes.

## Prompt A — Public verification page ✅ SHIPPED (2026-09-20)

**File:** `src/app/verify/[certNo]/page.tsx`

Public, unauthenticated Server Component that looks up a certificate by `certificate_no` via `createServiceClient()` (bypasses RLS by design — the security boundary here is the query's own field whitelist, not RLS) and renders a verification banner: VALID with learner name, course, organization, and issue date, or INVALID if no record matches. The `select()` must never include `final_grade`, `letter_grade`, or any other non-approved field — enforced by the `CertRow` type and by `page.test.tsx`'s explicit assertion that a grade present in fixture data never reaches the rendered DOM.

**Verification:** `npm run verify`; `page.test.tsx` covers valid, not-found, and DB-error paths.
