# COUNCIL-2026-040: Push Notifications and Mobile App

**Status:** DRAFT — pending council vote and owner approval
**Date:** 2026-09-26
**Council:** Architecture Council, ChurchCore LMS (vote pending)
**Related:** `public/manifest.json`, `src/app/offline/page.tsx`, notifications center, ChurchCore's `push_subscriptions` and `/api/push/subscribe` (the same design in the ChMS)
**Tags:** mobile, pwa, push, notifications, engagement

## Context

The LMS is an installable PWA (manifest plus offline page) without push notifications, and it isn't in the app stores. Church apps and course platforms reach learners on their phones. ChurchCore (the ChMS) already stores web-push subscriptions, so the product family has a precedent to follow.

## Decision (two phases)

**Phase 1: web push.**
1. A service worker with Web Push (VAPID). Learners opt in from the notification center; there's no prompt on first visit.
2. Events pushed:
   - new announcement;
   - graded submission;
   - a new message (including guardian threads from COUNCIL-2026-035);
   - course or path completion;
   - a live session starting in 15 minutes;
   - a daily streak reminder, off by default.
3. Preferences per event type live in `profiles.notification_prefs`. Every push also stays in the in-app notification center.

**Phase 2: store apps.**
4. A native wrapper around the production web app, using **Capacitor** (the same codebase with native push, deep links and a native share sheet), for the iOS App Store and Google Play. Choosing Capacitor over a React Native rewrite is a one-codebase decision and needs **ADR-2026-014** before Phase 2 starts.

## Amendments Adopted

Proposed; binding once voted.

1. **Push payloads carry no PII or content:** a title like "New message", a deep link, and no message text, grades or names of minors. The app loads the details after sign-in.
2. Subscriptions are org-scoped and deleted on sign-out, account deactivation or org suspension.
3. The VAPID private key and APNs/FCM credentials are server-side only.
4. Sending goes through a queue with retry and dead-letter (ADR-2026-010 pattern). An expired subscription (410) is deleted, not retried.
