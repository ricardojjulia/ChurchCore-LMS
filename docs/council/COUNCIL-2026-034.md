# COUNCIL-2026-034: Self-Serve Organization Signup and Trial

**Status:** DRAFT — pending council vote and owner approval
**Date:** 2026-09-26
**Council:** Architecture Council, ChurchCore LMS (vote pending)
**Related:** `docs/reviews/2026-09-26-mvp-competitive-status.md` (public-launch blocker #1), ADR-2026-003, COUNCIL-2026-032 (role and org only from `app_metadata`), `src/app/platform/actions.ts#createTenant`, `src/lib/stripe-plans.ts`
**Tags:** growth, onboarding, billing, tenancy, security

## Context

Every tenant is created by a platform admin (`createTenant` in the platform console). A church can't find the product, sign up and start a trial on its own. Every course platform and most church tools offer this. It is also the only path that exercises billing for real: no production organization has ever reached a Stripe customer.

## Decision

1. **Public signup at `/start`:**
   - church name, slug (unique, checked live), the admin's name and email, country/timezone and preferred language (en/es);
   - protected by Cloudflare Turnstile, as on `/join`;
   - the email must be verified before the tenant activates.
2. **Tenant provisioning** runs server-side through one service-role path (`provisionTenant`), which `createTenant` also uses:
   - the org is created in `trial` status with `trial_ends_at` = now + 14 days;
   - the admin's role and org go in `app_metadata`, never in `user_metadata` (COUNCIL-2026-032);
   - the org is seeded with the existing onboarding checklist (`/onboarding`) and one sample course, which the admin can delete.
3. **Trial to paid.**
   - A persistent trial banner appears in `/admin` with the days left.
   - A plan picker (starter, growth or enterprise, from `PLAN_FEATURES`) links to the existing Stripe checkout.
   - When the trial expires, the existing `expire-trials` Edge Function moves the org to a read-only "expired" state. Data is kept for 30 days, then handled through the existing soft-delete/purge lifecycle.
4. **Abuse controls:**
   - rate limits per IP and per email domain (Upstash);
   - disposable-email blocklist;
   - platform-admin review queue for flagged signups;
   - platform-admin alert on more than N signups per hour.
5. **Platform console** shows the signup source (self-serve or admin), trial status, and conversion.

## Amendments Adopted

Proposed; binding once voted.

1. One provisioning code path for both self-serve and admin-created tenants, covered by the same tests. No second tenant-creation implementation.
2. The slug check never reveals whether an email already has an account (no enumeration). "Slug taken" is allowed; "email already registered" is not shown, and a sign-in link is emailed instead.
3. Nothing is provisioned until the email is verified. Unverified signups expire after 24 hours and are deleted.
4. A tenant created by self-serve starts with `is_synthetic=false`, and the existing Stripe synthetic guard applies to it unchanged.
5. **Depends on `RESEND_API_KEY` being set in production.** Signup can't ship until app email works.

## Implementation Mandate

- Migration: `organizations.signup_source` (`admin` | `self_serve`), a `pending_signups` table (email hash, payload, expires_at, verified_at; no `anon` access; service role only), and indexes for trial expiry.
- Routes and actions:
  - `/start` page;
  - `POST /api/signup` (Turnstile, rate limit, validation, pending row, verification email);
  - `GET /api/signup/verify` (provisions the tenant, signs the admin in, redirects to `/onboarding`);
  - `provisionTenant()` in `src/lib/tenancy/provision.ts`.
- Marketing links from the public course catalog and `/login` ("Start your church's free trial").

## Test Surfaces

- `page:/start`: route table row (anonymous only; signed-in users are redirected); `flows/self-serve-signup.spec.ts` (sign up → verify → onboarding → trial banner → checkout started).
- `api:POST /api/signup`, `api:GET /api/signup/verify`: `tests/playwright/api/signup.spec.ts` (Turnstile failure, rate limit, duplicate slug, disposable domain, expired or reused token, no email enumeration).
- `action:provisionTenant` (via `platform/actions.createTenant` and signup): unit plus pgTAP (`app_metadata` role and org, trial dates).
