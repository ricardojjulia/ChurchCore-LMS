# COUNCIL-2026-023: Verify Deploy-Hook Releases Through Commit Status

**Status:** IMPLEMENTED AND VERIFIED LOCALLY — Architect review pending
**Date:** 2026-09-19
**Council:** Architecture Council, ChurchCore LMS (6/6 unanimous AI persona evaluation)
**Related:** COUNCIL-2026-022
**Tags:** release, vercel, observability, security

## Context

Production release 35364532446 applied the reviewed Supabase migrations and functions and received a successful Vercel status for commit `18df157`, but failed after 15 minutes. Its verifier searched for a GitHub Deployment created by `vercel[bot]`; the approved deploy hook does not create that record.

## Decision and amendments

1. Poll the commit-scoped `Vercel` status created after the deploy hook, not GitHub Deployments.
2. Require a successful status and a `https://vercel.com/` target URL; explicit error or failure remains terminal.
3. Preserve latest-main, environment-secret and Supabase target gates. No deployment, cloud database write, new dependency or Academy change is authorized by this repair.

## Council deliberation

- **Architect:** Match verification to the actual deployment integration. Yes.
- **Engineer:** Keep the change localized to the final verifier. Yes.
- **Security Lead:** Retain exact-SHA and post-trigger checks. Yes.
- **Product Owner:** Prevent false release failures that obscure a healthy delivery. Yes.
- **QA Lead:** Cover success, explicit failure and absent-status paths in workflow-shell checks. Yes.
- **Data Engineer:** No schema or data change. Yes.

## Definition of done

- [ ] Release verifier accepts only a post-trigger exact-commit Vercel success.
- [ ] Explicit Vercel failure remains a failed release.
- [ ] Version, documentation and factory evidence are updated.
