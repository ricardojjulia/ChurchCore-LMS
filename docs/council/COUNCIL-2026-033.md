# COUNCIL-2026-033 — Closing the COUNCIL-2026-031 Known Defects

**Date:** 2026-09-24
**Status:** Ratified
**Author:** Platform review, at the direction of the project owner (Ricardo Julia), who asked for every open item to be fixed
**Inputs:** COUNCIL-2026-031 findings (known defects), Copilot review #6, and defects found while fixing them

## Context

COUNCIL-2026-031 shipped the full test suite with its known defects recorded as `test.fail()` markers, 22 tolerated accessibility violations, and open follow-ups. This council closes all of them. Investigating them turned up more defects, some of them security issues, which are included here.

## Decisions

### Security

- **D1 — Nobody can set their own XP.** `award_xp(p_uid, p_amount)` was executable by `anon` and `authenticated`:
  - For `anon`, the guard `current_user_role() NOT IN (...)` evaluates to NULL and never raised, so **anyone could add unlimited XP to any profile**.
  - Students could award themselves XP.
  - Staff could award XP across tenants.

  Fix:
  - `award_xp` and `evaluate_badge_triggers` are service-role only.
  - `record_engagement_event` now derives XP itself (block `base_xp_reward`, quiz score, 100 XP for a verified completed enrollment) and rejects sources the caller isn't enrolled in. The caller's `p_xp` is ignored.
  - Assignment XP is awarded server-side, on the first attempt only.
- **D2 — No `anon` EXECUTE on SECURITY DEFINER functions.** The default grants let `anon` call every definer function in `public`, including the report view refresh (a cheap way to load the database). `anon` keeps only the nine RLS helper functions its policies evaluate. Signed-in users keep exactly what they had. `ALTER DEFAULT PRIVILEGES` covers new functions, and pgTAP `definer_grants_test.sql` pins both.
- **D3 — Demo tenants have no shared password.** Every demo reset used the hard-coded `Demo@2026!` and stored and displayed it, with guessable emails (`admin@<slug>.demo`). Production's Biblos tenant has 5 such accounts, including an admin, and they have been signed into.
  - Resets now set a random password that is never stored or shown.
  - Demo login uses a server-minted magic link redeemed in the same request, and compares tokens in constant time.
  - **Rotating the existing production demo passwords is an owner decision** (it locks out anyone using them); see Follow-up.
- **D4 — `/api/digest` fails closed.** It skipped authentication entirely when `CRON_SECRET` was unset. A shared `src/lib/cron-auth.ts` (constant-time, fail-closed) now guards it and the new scheduler route.
- **D5 — Releases deploy the approved commit (Copilot #6).** The Vercel deploy hook built whatever `main` was when it fired. The release job now runs `vercel build --prod` on the checked-out commit and `vercel deploy --prebuilt --prod`, authenticated by the `VERCEL_TOKEN` production secret. `VERCEL_DEPLOY_HOOK_URL` is no longer used.

### Functional defects

- **D6 — PDF generation works.** The project moves to **React 19** (Next 16 already rendered with its bundled React 19, which broke `@react-pdf/renderer` under React 18):
  - `@tremor/react` (React 18 only, used for one progress bar) is replaced by a native accessible progress bar.
  - `lucide-react` goes to 0.577 for React 19 peer support.
  - Certificate, student report and gradebook PDFs all download.
- **D7 — Large reports render inline.** The more-than-10-pages branch invoked Edge Functions that never existed and left "pending" artifacts forever. All exports now render in the request.
- **D8 — Weekly digest works end to end:**
  - `weekly-digest` called the session-only `/api/ai/weekly-summary` and was always rejected. It now calls the new cron-only `POST /api/cron/weekly-summary`, which shares its prompt logic via `src/lib/weekly-summary.ts` and uses no PII.
  - `verify_jwt = false` in `config.toml`, because the function authenticates with the cron secret.
  - Recipients are active students with `email_digest_enabled`. The flag it read before was never written anywhere.
  - Names and AI text are HTML-escaped.
  - Students get a "Weekly progress email" toggle on their profile.
- **D9 — Certificate verification works.** `/verify/[certNo]` reported every valid certificate as "No record matches" (ambiguous `profiles → organizations` embed, PGRST201). It now has positive and negative flow tests.
- **D10 — `/guardian/[studentId]` is guardian-only.** Staff were admitted by the page but refused by the RPC, so they saw a 404. They're now redirected to `/guardian`.
- **D11 — Managers can post org-wide announcements**, matching their org-lead role.

### Accessibility and performance

- **D12 — Zero tolerated accessibility violations.** All 22 `a11y-known.json` entries are fixed and the list is empty:
  - Contrast fixes; the platform billing page was unreadable at 1.09:1.
  - The feedback table no longer uses nested interactive rows.
  - Progress bars are named.
  - There is a single `#main-content`, and the sweep asserts it.
  - Builder `Field` labels are associated with their controls via `useId`.
  - About 40 other unlabelled controls get labels.
- **D13 — Prefetches skip the auth round trip.** A link prefetch that carries a session cookie no longer calls `getUser()` in middleware. That was about 28 calls per page view. The prefetched page still verifies the user when it renders.

## Follow-up (owner decisions)

1. **Rotate the Biblos demo accounts' passwords** in production (5 `@biblos-school.demo` users still accept `Demo@2026!`). Any real person signing in with them will be locked out; the platform console's one-time login link keeps working.
2. **Schedule `weekly-digest`** (for example Mondays 08:00 UTC with pg_cron, sending the cron secret). It emails every active student who hasn't opted out.
3. **Set `CRON_SECRET` in Vercel production.** It must equal the Supabase functions secret, or the digest route answers 401.
