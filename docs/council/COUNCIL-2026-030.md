**Status:** Ratified

## Context

Today, a teacher grading a course has exactly one surface: `/courses/[id]/submissions` (`src/app/courses/[id]/submissions/page.tsx`), a filterable list of `SubmissionCard`s, one per submission, each expanding to reveal a `GradeForm`. There is no at-a-glance view of "every student × every gradeable item" — a teacher must expand and grade one card at a time, which Council Review 3 called out as becoming unusable past ~15 students. A read-only summary table exists (`GradebookTable.tsx`, fed by the `get_gradebook_summary()` RPC) but it aggregates to one row per student (avg grade, submission count) — it cannot be used to enter grades, and it has no per-assignment columns.

**A real, pre-existing authorization gap was found while scoping this feature, and it is directly relevant to building a bulk-editing surface on top of it.** The active RLS policy on `block_submissions` for grading, `"block_submissions: staff grade own org"` (added in `supabase/migrations/20260618200200_org_id_rls_isolation.sql`, lines 287-297), checks only `current_user_org_id() = org_id AND current_user_role() IN ('admin','manager','teacher')` — it dropped the course-ownership check that the original policy (migration `20240601000027_learning_engine.sql`, lines 76-84) used to have. The application code doesn't compensate either: `gradeSubmission()` (`src/app/actions/learning.ts:496-540`) checks only that the caller's role is staff, never that the caller owns the course the submission belongs to. **Net effect: any teacher in an organization can currently grade any other teacher's course submissions**, via the existing single-grade UI or a direct API call. This has been true since `20260618200200` shipped and was never caught because no test exercises grading across two different teachers' courses in the same org. By contrast, the read-only `get_gradebook_summary()` RPC (`supabase/migrations/20250710090200_reporting_materialized_views.sql:114-154`) *does* enforce course ownership correctly for non-admins — it's the pattern to follow, not the pattern currently in force for writes.

This gap becomes materially more exploitable once a fast, grid-based bulk-editing surface exists (this feature), so it is fixed here as a corequisite, not deferred — the same judgment call COUNCIL-2026-027 made for its own pre-existing RLS recursion bug.

## Decisions

**D1 — Grid shape and route.** New route `/courses/[id]/gradebook`, staff-only (`admin`/`manager`/`teacher`), linked from the existing `/courses/[id]/submissions` page. Rows are the course's active student enrollments (`course_enrollments` where `role = 'student' AND status = 'active'`). Columns are the course's gradeable blocks — `course_blocks` where `block_type_id IN ('assignment', 'quiz')` and `is_published = true`, ordered by `sort_order` — the same filter `mv_academic_performance` already uses to decide what counts toward a grade. A cell with no `block_submissions` row yet renders as "not submitted," not an error.

**D2 — One RPC, ownership-checked like `get_gradebook_summary`, not like the current grading path.** New `get_course_gradebook_grid(p_course_id UUID)`, `SECURITY DEFINER STABLE`, mirroring `get_gradebook_summary`'s auth shape: role must be staff; if role is `teacher` (not `admin`/`manager`), the caller must own the course (`courses.owner_id = current_user_uid()`) or the function raises `Access denied`. Returns one row per (enrollment × gradeable block), `LEFT JOIN`ed against `block_submissions` so ungraded cells still appear.

**D3 — Per-cell save, not a batch transaction.** New server action `setGradeCell()` saves one cell at a time (score + optional feedback), following the exact interaction pattern already shipped in `AttendanceManager.tsx` — optimistic local update, `useTransition`, per-cell error bubble — rather than introducing a new all-or-nothing batch-commit concept. "Bulk grade entry" is solved by making single-cell entry fast across a full grid (tab/click through every student for one assignment, or every assignment for one student), not by a spreadsheet-paste import. CSV import/paste-in bulk entry is explicitly deferred (see D5).

**D4 — Fix the authorization gap from Context as part of this feature, not separately.** Two changes:
1. Restore the course-ownership check to `"block_submissions: staff grade own org"` for the `teacher` role specifically (`admin`/`manager` remain org-wide, matching existing precedent elsewhere in the app).
2. Add the same ownership check at the application layer in both the existing `gradeSubmission()` and the new `setGradeCell()` — defense in depth, consistent with the paranoia-level pattern `gradeDiscussionSubmission()` already uses elsewhere in the same file (`src/app/actions/learning.ts:667-686`).

This is a behavior change to existing, shipped code (a teacher who was relying on cross-course grading — which was never an intended capability — will be rejected going forward). That's the correct outcome per CLAUDE.md's tenant/permission-isolation rules; it is called out explicitly here rather than silently bundled in.

**D5 — Explicitly out of scope for v1.** Weighted grading (assignment categories/weights) and rubric-based grading are not part of this feature — every gradeable block today is a flat `score`/`max_score` pair, and neither concept has any existing schema support. Same for CSV bulk import (as opposed to export). These are real, separate features with their own scope and security surface; deferring them here matches the existing discipline around SCORM (ADR-2026-006) — revisit only if a concrete need surfaces, not preemptively. CSV **export** is in scope and needs no new backend code: the grid's already-fetched data is passed directly to the existing, generic `ExportCsvButton` (`src/app/courses/[id]/analytics/ExportCsvButton.tsx`), which takes `rows`/`filename` props and needs no changes.

**D6 — Grading an unsubmitted student is allowed (a real pattern in a church-education context — e.g. an in-person assessment recorded after the fact) and creates a new `block_submissions` row directly.** In that case there is no existing `block_submissions` row to update, so `setGradeCell()` must look up the student's `course_enrollments.id` (required, non-null FK on `block_submissions`) and insert a new row with `status = 'graded'`, `submitted_at = null`, `content = '{}'`, `attempt_number = 1` — distinct from the normal submit-then-grade flow, but reusing the identical post-grade side effects (D7).

**D7 — No duplicated grading side-effect logic.** `gradeSubmission()` today inline-implements XP award, in-app notification, optional Resend email, and guardian-notification-queue insertion (`src/app/actions/learning.ts:530-624`, ~90 lines). This is extracted into a shared `applyGradeSideEffects()` helper, called identically by the existing `gradeSubmission()` and the new `setGradeCell()` — so a grade entered via the new grid behaves identically (XP, guardian visibility, email) to one entered via the existing Submissions page, with zero behavior drift and zero duplicated logic.

## Prompt A — Migration: ownership-scoped grading RLS + gradebook grid RPC

**Files:**
- `supabase/migrations/20260922120000_gradebook_grid.sql` (NEW)

**Work:**
1. `DROP POLICY "block_submissions: staff grade own org" ON public.block_submissions;` and recreate it so `teacher` additionally requires course ownership, while `admin`/`manager` stay org-wide:
   ```sql
   CREATE POLICY "block_submissions: staff grade own org"
     ON public.block_submissions FOR UPDATE TO authenticated
     USING (
       public.current_user_org_id() = org_id
       AND (
         public.current_user_role() IN ('admin', 'manager')
         OR (
           public.current_user_role() = 'teacher'
           AND EXISTS (
             SELECT 1 FROM public.course_blocks cb
             JOIN public.courses c ON c.id = cb.course_id
             WHERE cb.id = block_submissions.block_id AND c.owner_id = public.current_user_uid()
           )
         )
       )
     )
     WITH CHECK (
       public.current_user_org_id() = org_id
       AND (
         public.current_user_role() IN ('admin', 'manager')
         OR (
           public.current_user_role() = 'teacher'
           AND EXISTS (
             SELECT 1 FROM public.course_blocks cb
             JOIN public.courses c ON c.id = cb.course_id
             WHERE cb.id = block_submissions.block_id AND c.owner_id = public.current_user_uid()
           )
         )
       )
     );
   ```
   Also apply the same `INSERT` shape as a new policy `"block_submissions: staff create graded own org"` (`FOR INSERT`, same `WITH CHECK`), since D6 requires staff to insert a submission row directly, not just update one — the existing policies only ever had staff *updating* rows students had already inserted.
2. `CREATE OR REPLACE FUNCTION public.get_course_gradebook_grid(p_course_id UUID) ... SECURITY DEFINER STABLE`, mirroring `get_gradebook_summary`'s role/ownership check exactly (role check `IN ('admin','manager','teacher')`, then for `teacher` require `courses.owner_id = current_user_uid()`, else `RAISE EXCEPTION 'Access denied'`). Query shape:
   ```sql
   SELECT
     ce.id            AS enrollment_id,
     ce.user_id       AS student_uid,
     p.display_name   AS student_name,
     cb.id            AS block_id,
     cb.title         AS block_title,
     cb.sort_order,
     bs.id            AS submission_id,
     bs.score,
     bs.max_score,
     bs.grade_pct,
     bs.status,
     bs.feedback
   FROM public.course_enrollments ce
   JOIN public.profiles p ON p.uid = ce.user_id
   CROSS JOIN public.course_blocks cb
   LEFT JOIN public.block_submissions bs
     ON bs.block_id = cb.id AND bs.user_id = ce.user_id AND NOT bs.is_deleted
   WHERE ce.course_id = p_course_id AND ce.role = 'student' AND ce.status = 'active'
     AND cb.course_id = p_course_id AND cb.block_type_id IN ('assignment', 'quiz') AND cb.is_published
   ORDER BY p.display_name, cb.sort_order;
   ```
3. `CREATE INDEX IF NOT EXISTS idx_course_enrollments_roster ON public.course_enrollments (course_id, role, status);` — supports the roster filter above at scale.
4. Comment in the migration explaining the ownership-check restoration and linking back to this council doc, so a future reader understands why the policy differs from the org-only shape used elsewhere.

**Security:** This is the load-bearing prompt. Verify directly against a real local Postgres instance that: (a) a `teacher`-role client can no longer `UPDATE` a `block_submissions` row belonging to a course owned by a different teacher in the same org (must fail before considering this done — reproduce the bug first, the same way COUNCIL-2026-027 proved its regression test meaningful); (b) `admin`/`manager` are unaffected; (c) `get_course_gradebook_grid` raises `Access denied` for a non-owning teacher and returns full data for the owner, `admin`, and `manager`.

**Verification:** `npm run typecheck`; direct psql/RLS check as described above.

## Prompt B — Backend: grid fetch action, per-cell grade action, shared side-effect helper

**Files:**
- `src/app/actions/gradebook.ts` (NEW)
- `src/app/actions/learning.ts` (MODIFIED — extract `applyGradeSideEffects()`, call it from `gradeSubmission()`)

**Work:**
1. In `learning.ts`, extract lines ~530-624 of `gradeSubmission()` (XP award, in-app notification, Resend email, guardian-notification-queue insert) into an exported `applyGradeSideEffects(sub: { user_id: string; block_id: string; max_score: number | null }, score: number, feedback: string): Promise<void>`. `gradeSubmission()` calls it after its own update — no behavior change, pure extraction. Cover with the existing `gradeSubmission` tests (`src/app/actions/learning.test.ts`) still passing unmodified.
2. `getGradebookGrid(courseId: string)` in `gradebook.ts`: auth check (redirect/`notFound()` pattern matching `src/app/courses/[id]/submissions/page.tsx`), call `supabase.rpc('get_course_gradebook_grid', { p_course_id: courseId })`, return typed rows (new `GradebookGridRow` type in `src/types/reporting.ts`, alongside the existing `GradebookSummary`).
3. `setGradeCell({ courseId, studentUid, blockId, score, feedback }: { courseId: string; studentUid: string; blockId: string; score: number; feedback: string })` in `gradebook.ts`:
   - Auth + role check identical to `gradeSubmission()`.
   - Ownership check (D4.2): fetch `course_blocks.course_id`/`courses.owner_id`/`courses.org_id` for `blockId` via `createServiceClient()` (mirroring `gradeDiscussionSubmission`'s cross-org check pattern, `learning.ts:667-686`); reject with the same `{ error: 'Not found' }` shape for both "doesn't exist" and "not yours," so the failure isn't a distinguishing signal; require `current org === courses.org_id` and (`role IN admin/manager` OR `courses.owner_id === profile.uid`).
   - Look up existing `block_submissions` row for `(blockId, studentUid)`. If found: `UPDATE` (same fields `gradeSubmission()` sets: `score`, `status='graded'`, `feedback`, `graded_by`, `graded_at`). If not found (D6): look up `course_enrollments.id` for `(courseId, studentUid, role='student')` — if no active enrollment exists, return `{ error: 'Student is not enrolled in this course' }` without writing; otherwise `INSERT` a new row (`enrollment_id`, `user_id: studentUid`, `block_id: blockId`, `attempt_number: 1`, `status: 'graded'`, `content: {}`, `score`, `feedback`, `graded_by`, `graded_at`, `submitted_at: null`).
   - Call `applyGradeSideEffects()` (D7) with the same shape `gradeSubmission()` does.
   - `revalidatePath('/courses/[id]/gradebook', 'page')`.

**Security:** `setGradeCell()`'s ownership check is the actual security boundary for this feature (Prompt A's RLS fix is defense-in-depth, not the primary gate, since this action uses the authenticated client for the write). Must reject a non-owning teacher with the same `{ error: 'Not found' }` shape used elsewhere in this file for cross-tenant/cross-course attempts — never a different error that would let a caller distinguish "wrong course" from "doesn't exist."

**Verification:** `npm run typecheck`; `npm test` (existing `learning.test.ts` must still pass after the extraction).

## Prompt C — Frontend: gradebook grid page and component

**Files:**
- `src/app/courses/[id]/gradebook/page.tsx` (NEW)

- `src/components/lms/GradebookGrid.tsx` (NEW)
- `src/app/courses/[id]/submissions/page.tsx` (MODIFIED — add a link to the new `/courses/[id]/gradebook` route)

**Work:**
1. `page.tsx`: Server Component, auth/role gate identical to `submissions/page.tsx`, fetches course title + `getGradebookGrid(courseId)`, renders `<GradebookGrid>`. `notFound()`/redirect shape matches the existing submissions page exactly (no new auth pattern introduced).
2. `loading.tsx`: skeleton matching the existing `submissions/loading.tsx` pattern (Council Review 3 flagged missing loading states elsewhere in the app — this route ships with one from day one rather than adding it later).
3. `GradebookGrid.tsx` (Client Component), modeled directly on `AttendanceManager.tsx`'s structure:
   - Sticky first column: student name + a client-computed running average (same `score/max_score` math as `grade_pct`, formatted like `GradebookTable`'s `gradeLetter()`).
   - One column per gradeable block (title + `max_score`), matching `AttendanceManager`'s column-header shape.
   - Each cell: a numeric `<input>` (not a dropdown, since grades aren't a fixed enum) defaulting to the current score or empty for "not submitted," saving via `setGradeCell()` inside `useTransition()` on blur (only if the value actually changed) — optimistic `Map<string, CellState>` update keyed by `${blockId}:${studentUid}`, identical structure to `AttendanceManager`'s `subs` Map; a small feedback-text affordance per cell (popover or expand-on-focus, reusing the textarea treatment from `GradeForm.tsx`); per-cell error bubble on failure, same `errors` Map + `setTimeout`-clear pattern as `AttendanceManager`.
   - Empty roster renders "No active students enrolled," matching `AttendanceManager`'s empty state.
   - Header row includes `<ExportCsvButton rows={...} filename={`${courseTitle}-gradebook.csv`} />` (D5) — flatten the grid to one row per student with one column per block title, computed client-side from already-fetched data; no new backend code.
4. Add a text link ("View gradebook grid →") from `submissions/page.tsx` to `/courses/[id]/gradebook`.

**Security:** No direct Supabase calls from `GradebookGrid` — only `setGradeCell()`, which enforces the ownership check server-side (Prompt B). The client never receives another course's data because `getGradebookGrid()` rejects at the RPC layer (Prompt A) before any row reaches the page.

**Verification:** `npm run typecheck`; `npm run lint`.
