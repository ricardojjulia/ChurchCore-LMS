# Minimal Check-In Policy

This repository is intended for lawful, constructive, and responsible use. To reduce the risk of abuse or misuse, every code or content check-in must follow these minimum rules:

1. **No secrets or private data**: Do not commit API keys, passwords, tokens, certificates, customer data, personal data, or confidential information.
2. **No harmful functionality**: Do not add malware, credential theft, evasion, unauthorized access, spam, phishing, surveillance, or abuse-enabling code or instructions.
3. **Respect authorization boundaries**: Code that interacts with systems, networks, accounts, or data must require proper authorization and must not bypass access controls.
4. **Safe AI and automation use**: AI-generated or automated changes must be reviewed before check-in. Do not commit prompts, agents, or automation that facilitate abuse, deception, or unsafe actions.
5. **Dependency hygiene**: Avoid unnecessary dependencies. Do not introduce known-vulnerable packages when a safer alternative is available.
6. **Security review for risky changes**: Changes involving authentication, authorization, cryptography, logging, personal data, external network access, deployment, or privileged operations require extra review.
7. **Traceability**: Use clear commit messages and pull request descriptions so reviewers can understand the purpose and risk of each change.

If a proposed change could enable harm or misuse, do not check it in until it has been redesigned, documented, and reviewed.
